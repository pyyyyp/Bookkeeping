# ADR-0014 视觉方向：深色科技感 + 语义色插槽

- 状态: **已接受**（2026-10-03，用户给出方向："参考现有记账软件，更有科技感一些"）
- 相关: `Q-020`（视觉设计未定 → **本 ADR 关闭它**）、`REQ-002`~`REQ-011`（记账页各区块）、`T-036`

## 背景

`Q-020` 从 `T-007` 挂到现在：`core/ui` 用 Material 3 默认色板，代码里写着
`TODO(Q-020)`，理由是"**没有设计稿就不编品牌色板** —— 编一套看起来专业但无人拍板的颜色，
会让后续真正的设计决策更难落地"。

用户现在给了方向：**参考现有记账软件，更有科技感一些**。
这句话仍然不是设计稿，所以本 ADR 把它**具体化成可执行、可推翻的 token**，
并把"什么情况下该推翻"写清楚。

## 决策 1：深色为主（Dark-first），并锁竖屏

**科技感**在记账 App 这个语境里最直接的做法是**深色 + 冷色高光 + 数据前置**：
深色让数字"发光"，而记账 App 的核心就是数字。

- 主题**默认深色**（`darkTheme = true`），但**保留浅色方案**（跟随系统时仍可用）。
- **锁竖屏**（`android:screenOrientation="portrait"`）：手机记账 App 的通行做法；
  也避免把竖屏布局拉伸到横向屏幕（这正是开发机上看到的那种"桌面感"）。

⚠️ 被否的方案：**跟随系统**（在浅色系统上就得不到"科技感"，用户的诉求落不了地）。

## 决策 2：颜色分两层 —— Material 3 的 role + 我们自己的**语义插槽**

Material 3 的 `ColorScheme` 里**没有**"支出/收入"这种业务含义的位置。
把它们硬塞进 `tertiary`/`error` 之类，会让"error 红"同时表示"出错了"和"花了钱"——
两个完全不同的意思共用一个槽位，迟早出错。

所以加一层 `LocalJizhangbaoColors`（`CompositionLocal`），提供：

| 插槽 | 用途 | 为什么单独一个 |
|---|---|---|
| `expense` | 支出金额 | 中国记账 App 习惯：支出暖色、收入冷/绿色 |
| `income` | 收入金额 | 同上 |
| `accent` | 结余、选中态、关键数字 | 它既不是支出也不是收入 |
| `muted` | 次要文字、单位、说明 | 避免到处 `onSurfaceVariant.copy(alpha=…)` |
| `cardBorder` | 卡片描边 | 深色下用**描边**表达层级，而不是阴影（深色里阴影几乎看不见） |

**色彩本身**（深色方案）：

```
background   #0B1020   深蓝黑（不是纯黑：纯黑配高饱和高光会"糊"，也没有科技感里的"空间"）
surface      #141B2E
surfaceVar   #1E2740
cardBorder   #2A3552
onSurface    #E6ECFF
onSurfaceVar #A8B3D0
accent       #22D3EE   青（关键数字、选中、结余）
secondary    #8B5CF6   紫（渐变/次级强调）
expense      #FF6B81   暖红
income       #34D399   薄荷绿
```

## 决策 3：层级用**描边 + 底色**，不用阴影

深色背景上阴影几乎不可见（没有可压暗的方向）。`ADR` 里写清楚，免得后来者加回阴影：
**卡片的层级 = 底色 + 1dp 描边**（`cardBorder`），重点卡片额外给一条 `accent` 描边。

## 决策 4：数字排印用**等宽数字**、标签用小号宽字距

- 金额一律 `FontFeatureSetting("tnum")`（等宽数字）→ 列表里数字**上下对齐**，
  这是"数据感"最廉价也最有效的一招。
- 主金额 34–40sp、字重中等、紧字距；标签 12sp + `letterSpacing 0.08em` → 仪表盘感。
- **不引入字体文件**（`res/font`）：那会增加体积，而系统字体 + 字距已经够用。

## 决策 5：不引入任何新的 UI 依赖

- ⚠️ **更正（`T-036` 实测）**：原写"图标只用 `material-icons-core` 里已有的"，
  但实测 `:feature:ledger` **取不到** `androidx.compose.material.icons`（unresolved reference）——
  它不在本模块的依赖里。**不为此加依赖**（为两个图标加一个包不值），改用**文字按钮**
  （编辑用强调色、删除用次要色）。这条更正是"先假设、被编译纠正、然后改文档"的正常流程。
- 图表**仍然不引图表库**：比例用**横向进度条**、趋势用**迷你条** —— 纯 Compose 画，
  零依赖，而且比引库更好控制（`Q-020` 的另一半"图表"因此可以在不引依赖的前提下做掉一部分）。

## 影响

- `core:ui`：主题重写 + `LocalJizhangbaoColors` + 一组通用组件
  （`AmountText` / `SectionCard` / `StatTile` / `BarRow`）
- `app`：`AndroidManifest` 锁竖屏
- `feature:ledger`：记账页按这套 token 重排（**逻辑一行不改** —— 纯展示层）
- `feature:worklog` / `feature:payroll`：下一张卡照同一套改
- ⚠️ **可推翻**：token 集中在**两个文件**（`Color.kt` / `Type.kt`）里，换色板是改常量，
  不动任何界面结构。若你要别的方向（浅色优先、更强的渐变、别的强调色），**改这里就行**。
