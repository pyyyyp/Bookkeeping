## 为什么它值得单独一张卡（而不是塞进 `T-033`）

`T-033` 的真机冒烟抓到一个缺口，但那时已经收尾：

> 月薪配的是 **2026-10-14** 生效，而当前月是 **10 月** → `effectiveAt(10-01)` 按 `Q-019`
> **正确地**返回"该月没有月薪"（**规则是对的**），但界面把它显示成「还没有配月薪」——
> **用户刚保存成功却看到"还没配"，看起来像保存失败**。

塞进 `T-033` 会让那一卡同时含"新功能 + 修缺口 + 补证据"三件事（`AGENTS.md` 第 7 节第 5 条
明令禁止混合提交）。所以单独一张卡。

## 真机验证（这一卡的主要价值）

配一份 **2026-01-01 生效**的月薪后，工资单页在真机上：

- **合计区**：`日薪（月薪 ÷ 21.75）` / `应付合计` / `与月薪的差额` / `21.75` 与「年平均值」的解释 / `367.82` ✓
- **逐日明细**（原样读到）：
  ```
  10-01 · 工作日 · 1× · ¥367.82
  10-02 · 工作日 · 1× · ¥367.82
  10-03 · 休息日 · 0× · ¥0.00
  ```
  ⚠️ 最后那行正是 `Q-012` 的「**不加班的周末没有**」—— 也正是 `T-033` 里我自己写错、
  被测试纠正的那件事。**两处独立地指向同一条规则**。
- **`AC-6` 的提示**：「这一年还没有节假日数据…按周末规则推定」（数据文件是空的）✓
- **月薪区**显示 `¥8000.00` + `2026-01-01` —— 说明"取该月生效的那一份"在真机上走对了 ✓

## 期间踩到的两个坑（都写进交接件）

1. **`adb shell` 会把参数重新拼接成一个字符串** → 引号在到 `sh` 之前就丢了
   （表现是 `unexpected '('`）。改用 **stdin** 灌 SQL（`$sql | adb shell … sqlite3 db`），
   一行引号都不用。之前那些 SELECT 能成，只是因为它们用的是**单引号**。
2. 写库前**先 `force-stop`**（教训 23：绝不往运行中的 Room 库里写）。
