# T-012 自定义分类

- 状态: **已完成**（9 条 AC 全部有证据；迁移在带真实数据的模拟器上验证过）
- 需求: `REQ-004`
- 上下文: Ledger
- 影响聚合: `Category`（**从值对象升级为聚合根**）、`LedgerEntry`（不受影响，只引用 id）

- 预估: 1.5 轮 | 实际:

## 目标

让用户加上自己真正在用的分类、把不用的收起来，而不是去迁就 8 个预置分类。

> **本卡第一次改数据库结构**（新增一张表 + `version` 1 → 2）。因此它比前几张卡多两件事：
> 写**迁移**，以及在**带真实数据的模拟器上**验证升级不清空账本（`REQ-004/AC-9`）。

## 变更清单

- [ ] 领域：`CategoryName` 值对象（非空白、1~20 字符，把 `MAX_NAME_LENGTH` 从 `Category` 挪过来）
- [ ] 领域：`Category` 升级为**聚合根**（`id` / `name` / `directions` / `archived`），
      行为：`rename(...)`、`archive()`、`restore()`；工厂 `create(...)` 与 `restore(...)` 分开
- [ ] 领域测试：改名 / 归档 / 恢复 / 名字非法被拒 / 已归档仍能读出名字
- [ ] 数据层：`category` 表 + `CategoryEntity` + `CategoryDao` + `CategoryMapper`
      + `CategoryRepositoryImpl`（`@Database` 加实体、`version = 2`）
- [ ] 数据层：**迁移 1 → 2**（`CREATE TABLE` + 索引），并**禁止** `fallbackToDestructiveMigration`
- [ ] 用例：`CreateCategoryUseCase`（**唯一性检查在这里**，`BR-7`）、`RenameCategoryUseCase`、
      `ArchiveCategoryUseCase`、`RestoreCategoryUseCase`、`LoadSelectableCategoriesUseCase`
- [ ] 用例测试（含"重名被拒"与"归档后不在可选清单里"）
- [ ] 记账界面：选择器改用**可选分类**（预置 ∪ 未归档自定义）；列表/编辑里的分类名解析
      改用**全部**分类（含已归档）—— 否则归档过的历史条目会显示成 id
- [ ] 界面：记账页顶部的分类管理入口 + 全屏对话框（新增 / 改名 / 归档 / 恢复；预置项只读并说明原因）
- [ ] `:app`：把新的 DAO 接进 `@Database`（组合根）
- [ ] 冒烟：建「宠物」→ 用它记一笔 → 改名看历史跟着变 → 归档后选择器里没有了但历史仍显示 →
      恢复 → **带真实数据升级验证迁移**（`AC-9`）
