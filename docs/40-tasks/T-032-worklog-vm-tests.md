这张卡把三条 AC 从"代码层"抬到"自动化"：

| AC | 原来的证据 | 现在 |
|---|---|---|
| `AC-7` 配置地点 | 代码层（真机拿不到定位） | `WorklogViewModelTest`：圆心就是拿到的那个点；名称空/半径非正不写 |

## 最值钱的那条断言

`AC-9 确认一段还在跑的时段_不存任何东西`。

`WorkSession.confirm()` 会拒绝（只有 `FINISHED` 能确认）—— 而界面这边的职责是
**不要把那个拒绝变成一次写入**。一个被"顺手确认"的、还没结束的时段，
在工资单上就是一段**凭空的工时**。这条链路的终点是钱，所以它值得一条自己的断言。

## 本轮踩到的坑（写进卡，也写进交接件教训表）

**测试方法名里不能有 ASCII 双引号**：Kotlin 用方法名生成 lambda 的 class 文件名，
而 `"` 在 Windows 路径里非法 → `InvalidPathException: Illegal char <">`，
编译器直接写不出文件。两次都栽在同一个地方（改完一条还有一条）。
与教训 17（仪器化方法名不能用非 ASCII）是相邻但不同的一条。
