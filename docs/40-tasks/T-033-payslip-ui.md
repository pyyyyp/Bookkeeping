## 展示粒度（`Q-029` 的决定，可推翻）

**合计区 + 全部逐日明细，不做折叠。**

理由：`REQ-013` 的核心是**可解释** —— 用户要能看出"为什么是这个数"。
31 行在滚动列表里完全不是负担（记账页本来就是一屏长列表），而折叠只增加交互复杂度、
还会让"某天为什么是 0"藏起来。

被否的方案：按周折叠（多一层状态、且"周"这个划分对工资没有意义）；
只显示合计 + 差额（丢掉了整个可解释性，等于把 `REQ-013` 的验收标准做没了）。
