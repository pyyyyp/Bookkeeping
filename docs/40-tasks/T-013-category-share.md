## 目标

在合计区下面回答"这个月的钱花在哪了"：按分类的金额与占比。

> **本卡最要紧的一条**：已归档的分类**必须计入**（`BR-2`）。
> 少算它，各分类之和就不等于支出合计 —— 两个数字并排显示在同一屏上，
> 用户一眼就能看出对不上。

## 变更清单

- [ ] 内核：`CategoryAmount`（分类名 + 金额）与 `CategoryBreakdown`（若干行 + 支出合计，
      派生 `shareOf(row)` 给出 1 位小数的占比；排序与空清单规则都在这里）
- [ ] 内核测试：占比四舍五入 / 三者各 33.3% 不凑百 / 金额降序且同额按名字 /
      合计为 0 → 空清单 / 单类 100.0%
- [ ] 端口：`LedgerTotalsReader` 增加 `expensesByCategory(range)`（复用 `ADR-0008` 的通路，
      不新增端口 —— 一个消费者、一个实现，多一个接口只是多一层）
- [ ] Ledger 实现：DAO 加"按分类求和"的查询 + 实现里把**分类名**解析出来
      （预置清单 ∪ 自定义**含已归档**，与 `REQ-004` 的显示名解析同源）
- [ ] Ledger 侧实现测试（fake DAO：求和与"已归档也算"）
- [ ] Insight：`LoadCategoryShareUseCase` + `MonthlyShareUiState` + `MonthlyShareSection`
      （跟着同一个月份，翻月一起变）
- [ ] Insight 用例测试（含空清单）
- [ ] `:app`：把占比区接到合计区下面（组合根里两个区共享同一个"当前月份"）
- [ ] 冒烟：真机上翻月看占比一起变；归档一个被引用的分类 → 占比仍与合计对得上
