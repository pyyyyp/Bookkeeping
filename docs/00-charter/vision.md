## 一句话定位

> 为 **按工时计酬的个人** 提供 **自动记账 + 自动工时记录 + 自动工资结算**，
> 解决 **「收入不固定、算不清自己挣了多少」** 的问题。

## 背景：与普通记账 App 的差别

普通记账 App 隐含假设「你有固定月薪，只需要记支出」，因此只回答「我花了多少」。
记账宝 面向的是**按小时/天计酬**的人（兼职、自由职业、临时工、同时做几份工），
它的差异化在于**同时回答「我挣了多少」以及「这份钱去哪了」**。

因此本项目的重点不是「记账」（那是通用域），而是 **工时 → 工资 → 每日收入** 这条自动化链路。

## 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---|---|---|
| 主要：按工时计酬的兼职/自由职业者 | 时薪或日薪、多份工作、收入按月或不定期结算 | 不用手动算工时和工资，知道「今天/这周挣了多少」 |
| 次要：有固定工作但有副业收入的人 | 主业月薪 + 副业按次计酬 | 分开追踪两份收入 |

## 核心价值主张

1. **消费不用手记** —— 监听通知栏自动捕获支出，识别不了时降级为手动（Q-001 已定）
2. **工时不用手算** —— 进出工作地点围栏时提醒，一次点击确认（Q-002 已定）
3. **工资不用手算** —— 工时 × 费率自动结算成工资单
4. **每天挣了多少一目了然** —— 工资按分摊规则展开为每日收入（**分摊规则待 Q-012**）

> 明确写出「我们**不**做什么」。Agent 遇到非目标内的需求必须拒绝并提问。

- ❌ **不上架应用商店**（自用侧载 + GitHub 开源）——但这**不**意味着可以滥用权限，仍须最小化采集
- ❌ 不做多用户协作、家庭共享账本、社交功能
- ❌ 不做发票管理、报销、税务申报
- ❌ 不做投资组合管理、行情、理财推荐
- ❌ 不做银行卡直连（Open Banking / 银企直连）

- ❌ 不做 Web 端 / 桌面端
- ❌ 不做多币种（v1）
- ❌ **不做「收入按比例分配到不同用途/目标」**——Q-003 已确认这不是本项目的需求
- 🔴 待确认：是否做云同步与多设备？v1 明确不做，仅做本地导出（见 Q-006）

## 成功度量

| 指标 | 目标 | 衡量方式 |
|---|---|---|
| 手工录入次数下降 | 相比纯手动记账减少 ≥ 70% | 本地统计 |
| 工时记录覆盖率 | 有围栏提醒的工作时段 ≥ 90% 无需手工补录 | 本地统计 |
| 记账连续性 | 连续使用 ≥ 30 天 | 本地统计 |
| 数据不丢失 | 换机后可通过导出文件完整恢复 | 手工验证 |

## 约束

| 类型 | 内容 |
|---|---|
| 团队规模 | 单人开发 |
| 后端 | 无，先用 Mock（`docs/50-contracts/`）；架构按离线优先设计 |
| 数据存储 | 纯本地（Room 为 SSOT） |
| **分发方式** | **自用侧载；后续可能开源到 GitHub。不上架应用商店** ⇒ 不受商店权限政策约束 |
| 所需敏感权限 | 通知使用权（捕获消费）、后台定位/地理围栏（工时）、可能的前台服务 |
| 隐私要求 | 通知监听在技术上可读取**全部**通知内容。**必须**声明数据不出本机，且只解析金融类通知 |
| 合规/开源 | 需 LICENSE；README 需写清构建前置条件；不得提交个人配置与密钥 |
