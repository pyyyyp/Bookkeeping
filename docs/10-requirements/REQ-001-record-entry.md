# REQ-001 手动记录一笔账目条目

- 状态: 已确认（2026-10-02，范围四项由用户逐条选定）
- 上下文: Ledger
- 优先级: P0
- 来源: 用户访谈 2026-10-02（**第一个业务需求**）
- 关联: `Q-005`（已解决）、`Q-008`（仍待确认，本 REQ 不使用记账日）、`Q-020`（视觉暂用 M3 默认）、`ADR-0005`、`ledger-model.md`

## 用户故事

作为 **按工时计酬的自用者**，我希望 **手工把一笔支出或收入记进账本**，
以便 **在不依赖通知监听的情况下账本依然完整**——
自动记账（`Q-001`）是加速器，不是前提；它没做好时我也必须能记账。

> 为什么这是第一个业务需求：它是**唯一不依赖任何未决问题**的端到端窄路径
> （`Q-015` 卡 Payroll、`Q-016` 卡 Calendar），
> 而且它会让 `:core:data` 的第一个 `@Entity` 由真实聚合自然倒推出来。

## 范围

**包含**：

- 记一笔：**金额 + 收支方向 + 分类 + 发生时间 + 备注（可选）**
- **收入与支出都做**（`EntryDirection` 已是领域核心概念，UI 上只是二选一）
- 在账本列表里看到已记的条目（按**发生时间**倒序）
- 补记：发生时间默认「现在」，可以改成过去的日期
- 删除一条记错的条目（二次确认）

**不包含**（明确写出，防止范围蔓延）：

- ❌ **账户与余额**——`Q-005` 已决：v1 不做（见 `ADR-0005`）
- ❌ 多币种——`Q-005` 一并决为不做
- ❌ **编辑已保存的条目**（改金额 / 分类 / 时间）——另开一张卡
- ❌ **自定义分类**——本卡只有预置分类，自定义另开一张卡
- ❌ 汇总、统计、图表（属于 Insight 上下文）
- ❌ 通知监听自动记账（`Q-001`，后续任务）
- ❌ 记账日 `bookingDate`——`Q-008` 未定，**本 REQ 不引入该概念**
- ❌ 撤销删除——删除即不可恢复（见 `ADR-0005`）
- ❌ 未来时间的账——本卡不校验，记 `Q-021`

## 验收标准

> 业务语言，不提技术实现。AC 编号一旦分配不复用。

### AC-1 记一笔支出

```
Given 账本中有预置分类「餐饮」
When  我输入金额 12.50、选择「支出」与「餐饮」，并保存
Then  账本中出现一条 12.50 元的支出条目，分类为「餐饮」，
      发生时间为当前时间
```

### AC-2 记一笔收入

```
Given 账本中有预置分类「工资」
When  我输入金额 8000、选择「收入」与「工资」，并保存
Then  账本中出现一条 8000 元的收入条目
```

### AC-3 金额必须是正数且不超过两位小数

```
Given 我在记账界面
When  我输入的金额为 0、或为负数、或超过两位小数（如 12.345）
Then  该金额不被接受，我看到明确的提示，且账本中不会产生任何条目
```

### AC-4 必须选择分类

```
Given 我在记账界面且已输入合法金额
When  我没有选择分类就尝试保存
Then  保存不生效，我看到「请选择分类」的提示，账本中不会产生条目
```

### AC-5 补记：发生时间可以改成过去

```
Given 今天是 10 月 3 日
When  我把发生时间改为 10 月 1 日并保存
Then  该条目记为 10 月 1 日发生；列表按 10 月 1 日的顺序排列它，
      而不是按「我什么时候录入的」排列
```

### AC-6 备注可选

```
Given 我在记账界面
When  我不填备注直接保存
Then  条目保存成功，备注为空
```

### AC-7 列表按发生时间倒序显示条目

```
Given 账本中有 10 月 1 日与 10 月 3 日各一条条目（录入顺序相反）
When  我打开账本列表
Then  10 月 3 日的条目显示在 10 月 1 日的上方，
      每条都显示金额、方向、分类与发生日期
```

### AC-8 删除需要二次确认，取消则不删

```
Given 账本中有一条条目
When  我触发删除，并在确认弹窗中选择「取消」
Then  该条目仍然存在，列表不变
```

### AC-9 确认删除后条目不再存在

```
Given 账本中有一条条目
When  我触发删除并确认
Then  该条目从列表中消失；重启应用后也不会再出现
```

### AC-10 条目持久化（本机唯一事实源）

```
Given 我记录了一笔支出
When  我完全关闭并重新打开应用
Then  该条目仍然存在，内容（金额/方向/分类/发生时间/备注）与记录时一致
```

## 非功能约束

- 性能：列表首屏 ≤ 200 条时无明显卡顿（本机、离线）
- 离线：**完全离线可用**；本 REQ 不涉及任何网络
- 安全/隐私：不申请任何新权限；数据只写本机数据库（与 `PRIVACY.md` 一致，**引入存储需同提交更新它**）
- 可访问性：金额输入框与分类选择可用 TalkBack 读出；触控目标 ≥ 48dp

## 业务规则

| 编号 | 规则 | 落到哪个聚合 | 不变式编号 |
|---|---|---|---|
| BR-1 | 金额以「**分**」为单位存储，不可为负；方向由 `EntryDirection` **显式**表达，不用正负号 | `LedgerEntry` | INV-1 |
| BR-2 | 条目金额必须**大于 0**（金额为 0 的条目没有意义） | `LedgerEntry` | INV-1 |
| BR-3 | 每条条目**必须有分类**；分类只能取自账本中已有的分类 | `LedgerEntry` | INV-2 |
| BR-4 | 方向只能是 `Expense` 或 `Income` | 类型系统（enum） | INV-3 |
| BR-5 | 删除是**物理删除**，二次确认后不可恢复（理由与被否方案见 `ADR-0005`） | 仓储 + UI | INV-4 |
| BR-6 | 本卡分类来自**预置集合**，不能新增分类 | `Category` | — |
| BR-7 | 备注可空；填写时长度 ≤ 200 字符 | `LedgerEntry` | INV-5 |

> ⚠️ **刻意没有写的规则**：是否允许记录**未来时间**的账（`Q-021`），
> 以及是否需要「记账日」（`Q-008`）。不确定就不写——不许用「通常」「一般」含糊过去。
