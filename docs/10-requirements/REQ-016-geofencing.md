# REQ-016 地理围栏自动记录工时

- 状态: 待实现
- 优先级: P1
- 上下文: Worklog（核心域）
- 提出: 2026-10-03
- 前置: `Q-024`（用户拍板：做）、`ADR-0013`（技术路线与五条决策）、`REQ-014`（工时与出勤事实）

## 用户故事

我不想每天手填"9 点到 18 点"。我到了干活的地方它就该自己开始记，
走了就该自己停 —— 然后**由我点头确认**，因为定位会漂，而钱不能跟着漂。

## 背景

`REQ-014` 的手工记录能跑，但**每天两次手填**是这类 App 最容易半途而废的地方。
地理围栏是 Worklog 的原始机制（问卷里就是这么写的）。

代价原本写着两条：**新依赖** + **权限**。核实目标设备后第一条**消失了** ——
MuMu 上**没有 Google Play 服务**（`pm list packages` 里没有 `com.google.android.gms`），
所以 Play Services Location 在那台设备上根本跑不起来；用系统 `LocationManager` 即可，
**一个第三方依赖都不用加**（`ADR-0013` 决策 1）。

真正要付的代价是**权限**：这个 App 从此**不再是"没有任何权限"**。

## 范围

**做**

- `Workplace`（工作地点：名称 + 坐标 + 半径）
- **纯函数**的半径判定（Haversine）与状态迁移（进入/离开/抖动）
- 系统定位的 ACL 实现（`LocationManager`），**仅 App 运行时**
- 进入 → 建 `RUNNING` 时段；离开 → `FINISHED`；**用户确认后才 `CONFIRMED`**
- 权限缺失时的**退化**：不崩、不静默（回到手工记录，并说明原因）

**不做**

- **后台定位**（`ACCESS_BACKGROUND_LOCATION`）—— `ADR-0013` 决策 3：v1 只在 App 运行时记录
- **自动确认**：定位不是"在上班"的证据（`ADR-0013` 决策 4）
- 地图选点（地图 SDK 是**新依赖**，须先问）—— 改用"把**当前位置**设为圆心"（`AC-7`）
- 固定班次、迟到早退（`Q-009`）

> ⚠️ **界面原本也写在这里的"不做"里，`T-031` 已把它补上**（`AC-7`~`AC-10`）——
> 与 `T-029` 补持久化是同一种做法：同一个需求的能力被推迟到后续任务卡，比另开需求诚实。

## 验收标准

### AC-1 进入围栏 → 开始一段"进行中"的工时

**给定** 一个已配置的工作地点（坐标 + 半径）
**当** 位置从圈外进入圈内
**那么** 新建一段 `RUNNING` 的工时，归属日是**进入那天**

### AC-2 离开围栏 → 结束它，但**还不算事实**

**当** 位置离开圈内
**那么** 那段工时变成 `FINISHED`（有结束时刻）——
⚠️ 而**不是** `CONFIRMED`：`AttendedDay` 只认已确认的时段（`REQ-014/AC-2`），
所以围栏**不可能**直接改变工资。

### AC-3 只有用户确认过的时段才算数

**当** 用户确认一段
**那么** 它变成 `CONFIRMED`，此后才可能出现在出勤事实里

### AC-4 离开不足 10 分钟不算离开

**给定** 一段进行中的工时
**当** 离开围栏 3 分钟后回来
**那么** **仍然是同一段**（不结束、不新建）
**当** 离开 15 分钟
**那么** 那一段在**离开那一刻**结束（不是 15 分钟后才结束），之后再进来是新的一段

### AC-5 没有位置权限时不崩、也不静默

**当** App 没有位置权限
**那么** 自动记录**不启动**，且界面能说明"缺少位置权限"（回到手工记录这条路仍然可用）
—— 静默失效最糟：用户会以为"今天没上班"（`REQ-006` 的教训）

### AC-6 判定是纯函数，边界说得清

**当** 位置正好落在半径上
**那么** 算**在圈内**（`<=`，含边界）；跨经线（东经 179° 到西经 179°）距离计算正确
—— 这一条要求判定跑在 JVM 上、可被单测，而不是依赖某个平台 API 的黑盒行为

### AC-7 配置一个工作地点（`T-031`）

**当** 用户填名称、用**当前位置**作为圆心、给一个半径
**那么** 这个工作地点被保存下来，并且之后的定位更新按它判定
—— ⚠️ **不用地图选点**：地图 SDK 是新依赖（须先问），而"我现在就在干活的地方"
是配置这个场景最自然的输入方式

### AC-8 权限能在界面上申请，且拒绝后说得清（`T-031`）

**当** 用户点「开启自动记录」而权限未授予
**那么** 系统权限对话框弹出；**拒绝之后界面明确说明"缺少位置权限，自动记录未开启"**，
并且手填工时这条路**仍然可用**
—— 这一条给 `AC-5` 补上**真机可见的那一面**（`AC-5` 原本只有代码层证据）

### AC-9 围栏产生的时段能被确认（`T-031`）

**当** 界面上列出围栏产生的时段（`RUNNING` / `FINISHED`）
**那么** 用户能**确认**它（→ `CONFIRMED`，此后才进出勤事实）、也能**作废**它
—— 这是"系统只记录、人确认"（`ADR-0013` 决策 4）的**落地点**：没有它，围栏产生的时段
永远停在 `FINISHED`，一分钱也不算

### AC-10 工作地点存得住（`T-031`）

**当** 配置好工作地点后重启 App
**那么** 它还在（加表 + 手写迁移，与 `REQ-014/AC-7` 同样的验证方式）

## 业务规则

- **BR-1 规则归自己，平台只取数**（`ADR-0013` 决策 2）：半径判定与状态迁移是纯函数；
  `LocationManager` 只负责把坐标送进来。
- **BR-2 围栏只记录、不判定**（`ADR-0013` 决策 4）：它会出门就触发，
  所以它**没有**权限把工时变成"事实"——那需要人确认。
- **BR-3 抖动是常态，不是异常**（`Q-027`）：离开不足 10 分钟视为同一段连续工作。
- **BR-4 v1 只在 App 运行时记录**：不申请后台定位。"App 没开就不记"是**明说的范围**，
  不是疏漏。
- **BR-5 坐标不进日志**（`ADR-0010`）：它属于 PII，只落在本机数据库。
