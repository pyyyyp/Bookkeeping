# REQ-014 工时记录与出勤事实

- 状态: 待实现
- 优先级: P1
- 上下文: Worklog（核心域）
- 提出: 2026-10-03
- 前置: `Q-012`（工时不参与金额计算）、`ADR-0012`（读通路与门槛归属）
- 下游: Payroll（用它算加班与缺勤）

## 用户故事

我要能记下"我今天 9 点到 18 点干活了"，然后让系统知道**这一天出勤了** ——
因为工资是按天算的（`Q-012`），而"哪天算加班"直接决定倍数。

## 背景

Worklog 的原始机制是**地理围栏**，但它撞上两条**必须问的红线**（`Q-024`）：
**新依赖**（Play Services Location）与**位置权限**（后台定位还要额外申请）。
而现在这个 App 的卖点之一是"**没有任何权限**"（`T-020` 的发布清单核实过）。

所以 v1 先做**手工记录**：自己填一段工作时间的起止。它把"哪天出勤"这件事跑通，
**不引入任何依赖与权限**；地理围栏作为独立需求另开。

## 范围

**做**

- 记录一段工作时间：起止时刻 + 归属日
- 只有**已确认**的时段计入出勤（`Running` / `Finished` / `Discarded` 都不算）
- 出勤日的**已确认分钟数**（同一天多段要合并）

**不做**

- **地理围栏**（`Q-024`：新依赖 + 权限，必须先问）
- 界面（本轮只交付领域与规则）
- 固定班次 / 迟到早退（`Q-009`）
- **加班门槛**（满 8 小时算 1 天）—— 那是**钱**的规则，归 Payroll（`ADR-0012` 决策 2）
- 缺勤标记（`Q-026`：v1 按正常出勤处理）

> ⚠️ **持久化原本也写在"不做"里，`T-029` 已把它补上**（见下面 `AC-6` / `AC-7`）。
> 一个需求的能力被推迟到后续任务卡，比另开一个需求更诚实 —— 它还是同一件事。

## 验收标准

### AC-1 记录一段工作时间

**当** 记录 `09:00–18:00`、归属日为某一天
**那么** 得到一个该日的 `Confirmed` 时段（手工录入时**用户的录入本身**就是确认）

### AC-2 只有「已确认」的时段计入出勤

**给定** 同一天有若干时段，状态各不相同
**当** 取出勤日
**那么** 只有 `Confirmed` 的那些算 —— `Running`（还在跑）、`Finished`（跑完但未确认）、
`Discarded`（作废）**都不算**。一个还在跑的时段不能变成工资

### AC-3 出勤日的分钟数是该日已确认时段之和

**给定** 同一天上午 `09:00–12:00`、下午 `13:00–18:00` 两段已确认
**那么** 这一天的出勤分钟数是 `8` 小时（两段相加，不取"最外层的跨度"——
中间那顿午饭不是工时）

### AC-4 跨午夜的时段归属于它**开始**的那一天

**给定** `22:00–次日 02:00` 的一段
**那么** 它计入**开始**那天。
⚠️ 这是**明确写下的局限**：夜班跨天时，"哪天算加班"本来就需要人拍板（v1 不拍）

### AC-5 没有已确认时段的日期不出现在结果里

**那么** 出勤结果是**只含有事实的那些天**，而不是"整月每天一条、没有的填 0"
（"这天没记录"与"这天出勤 0 分钟"是不同的两件事 —— 后者会诱导调用方按缺勤处理）

### AC-6 工时存得住（`T-029`）

**当** 记录一段工时、然后重新读出来
**那么** 它还在，且**状态与时刻都不变** —— `Running` 的时段重读后仍是 `Running`
（"结束时刻为空"这件事也要原样保留）

### AC-7 升级不丢已有数据（`T-029`）

**给定** 一个已经有账目数据的 2 版数据库
**当** 装上升级后的版本（3 版）
**那么** 新表建好、`user_version = 3`，而**已有的账目一行不少、金额分毫不差**

> 加表不动旧表，所以这次升级**不可能**碰到用户已有的账 —— 但这句话必须被**真机验证**，
> 不能只是推理（`REQ-004/AC-9` 是同一套做法：真机 + `sqlite3` 直查）。

## 业务规则

- **BR-1 工时不经手钱**（`Q-012`）：Worklog 只说"这天工作了多少分钟"，
  倍率、门槛、金额都是 Payroll 的事。**Worklog 不认识 Calendar，也不认识 Money。**
- **BR-2 状态机是四态**：`Running` / `Finished` / `Confirmed` / `Discarded`（glossary）。
  只有 `Confirmed` 是**事实**；其余是过程中的状态。
- **BR-3 手工录入即确认**：没有围栏可校验时，用户的录入**就是**断言。
  （`Running`/`Finished` 是给将来的围栏流程留的，`ADR-0012` 决策 3。）
- **BR-4 段与段相加，不合并跨度**：两段之间的时间不是工时。
- **BR-5 缺勤不是本上下文的事实**：`Q-026` 决定"没记录"按正常出勤处理 ——
  Worklog 因此**不能**用"没有记录"造出一个"缺勤"的假事实。
