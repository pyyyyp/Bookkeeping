# REQ-013 日收入与工资单（纯计算）

- 状态: 待实现
- 优先级: P1
- 上下文: Payroll（核心域）
- 提出: 2026-10-03
- 前置: `Q-012`（算法）、`Q-015`（带薪规则，已定案）、`Q-017`/`Q-018`/`Q-019`（已定案）、`REQ-012`（日期类型）

## 用户故事

记账 App 只回答"我花了多少"，而我要的是**"我这个月该拿多少"** ——
而且要能**逐日解释**：每一天为什么是 1×、2×、3× 还是 0。
拿到工资条那天，我要能一眼看出某个数字是怎么来的。

## 背景

算法本身（`Q-012`）是清楚的：`日薪 = 月薪 ÷ 21.75`，再按日期类型与是否出勤乘倍率。
真正容易做错的是**三件小事**：

1. **取整**：`8000 ÷ 21.75 = 367.8160919…`。留在浮点里，工资单就会出现
   `367.816091954023` 这种数字，而且对不上分。
2. **带薪规则**：法定节假日**休息也带薪**（`Q-015`），而缺勤**不计**（同）。
   这两条是 0 与 1× 的分界，直接决定金额。
3. **对不上月薪**：任意单月的日收入之和**不会**正好等于月薪（21.75 是年平均值）。
   想"凑齐"就会引入无法解释的调整项 —— 正确的做法是**把差额显示出来**。

## 范围

**做**

- 由 `MonthlySalary` 折算 `DailyRate`（整数运算、四舍五入到分）
- 逐日算 `DailyIncome`（六种情形，见 `payroll-model.md` 的表）
- 汇总成 `Payslip`，含 `amountDue` 与 `differenceFromSalary`

**不做**

- **出勤/加班的判定**（那是 Worklog 的事，还没实现）。本轮把 `worked` / `absent`
  当**参数**收进来 —— 不造假的 Worklog，也不猜
- 界面（没有页面）
- 多份工作合并出单、按周/半月结算（`Q-004` 还在）
- 涨薪后的历史重算（`effectiveFrom` 字段先落，查询未实现）

## 验收标准

### AC-1 日薪按 21.75 折算，四舍五入到分

**给定** 月薪 `¥8000.00`
**当** 折算日薪
**那么** `¥367.82`（`8000_00 × 100 ÷ 2175 = 36781.6…` → 进位到分），
且**全程整数运算**（钱不经过 `Double`）

### AC-2 工作日：出勤 1×，缺勤 0

**给定** 某工作日
**当** 该日出勤 / 缺勤
**那么** 分别是 `1 × 日薪` / `0`

### AC-3 休息日：加班 2×，不加班 0

**给定** 某休息日
**当** 加班 / 不加班
**那么** 分别是 `2 × 日薪` / `0`

### AC-4 法定节假日：加班 3×，休息 1×（带薪）

**给定** 某法定节假日
**当** 加班 / 休息
**那么** 分别是 `3 × 日薪` / **`1 × 日薪`**（`Q-015` 定案：休息带薪）

### AC-5 工资单汇总并显示与月薪的差额

**给定** 一个月的逐日收入
**当** 汇总
**那么** `amountDue = Σ 各日收入`，并且 `differenceFromSalary = amountDue − 月薪`
**如实显示** —— 不为了凑齐月薪而加调整项

## 业务规则

- **BR-1 月计薪天数是法定常量**：`21.75 = (365−104)÷12`。它不等于任何单月的实际天数，
  所以"日收入之和 ≠ 月薪"是**预期的**。
- **BR-2 钱不经过浮点**：日薪用「分 × 100 ÷ 2175，四舍五入」算。
  与 `REQ-005` 占比用整数千分点是同一个理由。
- **BR-3 带薪规则照 `Q-015`**：缺勤 `0`；法定节假日休息 `1×`。
- **BR-4 判定权在 Calendar**：Payroll 只**消费** `DayType`，不自己判"哪天是节假日"
  （`ADR-0011` 决策 4）。
- **BR-5 出勤与否不由 Payroll 猜**：没有 Worklog 就没有出勤事实；
  本轮的输入是参数，不是"默认出勤"。
- **BR-6 纯计算、无聚合**：`Payslip` 是算出来的读模型，重算即得同一结果。
