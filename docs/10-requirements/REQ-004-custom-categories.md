# REQ-004 自定义分类

- 状态: 待实现（**阶段 B / C 已完成**：需求 + 决策 + 任务卡；实现见 `T-012`）
- 上下文: Ledger
- 提出: 用户（2026-10-02，在 `REQ-003` 完成后的候选里选了本项）
- 关联 ADR: `ADR-0009`（分类的生命周期）、`ADR-0005`（v1 范围：预置只读）、`ADR-0007`（数据层归属）

## 用户故事

> 作为一个实际在记账的人，
> 我想加上自己真正在用的分类（「宠物」「话费」「人情」），把不用的收起来，
> 这样列表里的归类能对上我的生活，而不是我去迁就应用的 8 个预置分类。

## 范围

**做**：

- **新建**自定义分类：名字 + 它支持哪些收支方向（支出 / 收入 / 两者）
- **重命名**自定义分类
- **归档**（收起来）与**撤销归档**；归档后不出现在记账时的分类选择器里
- 分类管理入口在记账界面顶部（**全屏对话框**，不引入导航依赖）
- 新分类**立刻**可以用于记账；改名后历史条目**显示**新名字
- 已归档的分类仍能把历史条目的分类名显示出来（历史不悬空）

**不做**（写清楚，避免"顺手加"）：

- **物理删除**分类（见 `ADR-0009`：历史条目引用了它，删掉要么留悬空引用、要么改写历史）
- 修改**预置**分类（`餐饮` `交通` `购物` `居住` `医疗` `娱乐` `工资` `其他`）——v1 保持只读
  （`ADR-0005` 的取舍延续；哪天真要改，是另一个需求）
- 分类的排序 / 拖拽 / 图标 / 颜色
- 分类层级（父子分类）
- 预算、按分类的报表（那是 Insight 的事，另一个需求）
- 导入导出分类

## 验收标准

> 业务语言，不提技术实现。AC 编号一旦分配不复用。
> ⚠️ 格式必须是 `### AC-n <标题>`（追溯脚本按这个模式抓取）。

### AC-1 新建分类并立刻可用

```
Given 我在分类管理里
When  我新建一个叫「宠物」、只用于支出的分类
Then  它出现在**支出**方向的选择器里
      我立刻记一笔支出、选中「宠物」并保存 —— 这笔账的分类显示为「宠物」
```

### AC-2 重命名后历史条目跟着显示新名字

```
Given 有一条历史账用的分类是「宠物」
When  我把这个分类改名为「猫主子」
Then  选择器里显示「猫主子」
      并且那条历史账也显示「猫主子」（是同一个分类改了名，不是复制出一份新的）
```

### AC-3 归档后不再出现在选择器，但历史条目照旧显示

```
Given 分类「宠物」下有一条历史账
When  我把它归档
Then  记账时分类选择器里**没有**「宠物」
      但那条历史账仍显示「宠物」（历史不因为收起来就变得看不懂）
```

### AC-4 归档可以撤销

```
Given 我已经把「宠物」归档
When  我在已归档列表里把它恢复
Then  它重新出现在选择器里，可以继续用
```

### AC-5 同名分类被拒绝

```
Given 已经有一个（未归档的）叫「宠物」的分类
When  我再新建一个也叫「宠物」的分类
Then  提示名字已存在，**不创建**第二个
```

### AC-6 名字不合法时被拒绝

```
Given 我在新建或改名
When  名字留空、只有空格、或超过 20 个字
Then  给出提示并拒绝（与分类名既有的长度规则一致）
```

### AC-7 预置分类是只读的

```
Given 我在分类管理里看预置分类「餐饮」
Then  它没有改名或归档的入口（内置内容只读）
      界面说明了这一点，而不是让按钮点了没反应
```

### AC-8 归档一个仍被引用的分类不会破坏那些条目

```
Given 分类「宠物」被 3 条账引用
When  我把它归档
Then  那 3 条账仍正常显示「宠物」，金额与本月合计**都不受影响**
```

### AC-9 升级后原有数据都在

```
Given 我已经在用旧版本，账本里有多条账与合计
When  我升级到带自定义分类的版本
Then  所有原有条目都还在、显示正常、合计不变（升级**不清空**数据）
```

## 业务规则

| 编号 | 规则 | 理由 |
|---|---|---|
| `BR-1` | 分类**只能归档，不能物理删除** | 历史条目引用了它（存的是 id）：物理删除要么留下悬空引用，要么得改写历史、悄悄改变过去某笔账的含义。见 `ADR-0009` |
| `BR-2` | **预置分类只读**（不可改名、不可归档） | v1 的取舍（延续 `ADR-0005`）。内置内容与用户内容是两种东西，混在一起会让"恢复默认"变得含糊 |
| `BR-3` | 名字在**未归档**的分类之间必须唯一（忽略前后空格与大小写） | 两个都叫「宠物」的分类，用户在记账时无法区分 |
| `BR-4` | 名字长度与既有规则一致（1 ~ 20 字符） | 沿用 `Category` 已有的 `MAX_NAME_LENGTH`，不新造一套 |
| `BR-5` | 归档的分类不出现在**选择器**里，但仍能解析出名字 | 选择器是"现在能用的"，历史是"当时用的"，两件事不能混 |
| `BR-6` | 重命名立即影响历史的**显示**，但**不改写任何条目** | 条目只存分类 id，所以改名天然不会碰条目 —— 这正是存 id 而不是存名字的价值 |
| `BR-7` | 唯一性检查放在**应用层**，不是聚合不变式 | "所有分类里不能重名"是**跨聚合**的规则，DDD 上不属于单个聚合的职责。放进 `Category` 的 `init` 会得到一个测不准、也无法在聚合内验证的规则 |
| `BR-8` | 分类的**方向集合**决定它出现在哪个方向的选择器里 | 沿用既有模型（`directions: Set<EntryDirection>`），不改 |
