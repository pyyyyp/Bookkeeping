# REQ-002 本月收支合计

- 状态: 待实现（**阶段 B / C 已完成**：需求 + 读模型 + 架构决策 + 任务卡；实现见 `T-009`）
- 上下文: Insight（读模型）

- 关联 ADR: `ADR-0008`（跨上下文读模型的数据通路）

## 用户故事

> 作为一个按工时计酬、平时用这个 App 记账的人，
> 我想在记账界面一眼看到**这个月一共花了多少、挣了多少、还剩多少**，
> 这样我不用自己拿计算器把列表里的数字加一遍。

## 范围

**做**：

- 显示**当月**的：支出合计、收入合计、结余（收入 − 支出，**可以是负数**）
- 可以切到**上一个月 / 下一个月**（默认当月）；切到未来的月份没有意义，所以「下一月」在当月时禁用
- 空月份显示 `¥0.00`，并说明本月还没有记账
- 合计金额跟随列表即时更新（记一笔、删一笔之后立刻变）
- 只读：统计区不提供任何修改数据的入口

**不做**（写清楚，避免"顺手加"）：

- 分类占比、趋势图、跨月对比、年度汇总
- 导出 / 分享
- 预算与超支提醒（那是另一个需求，涉及"预算"这个新概念）
- 按周/按日聚合
- 账户维度（`ADR-0005` 已决定 v1 无账户）

### AC-1 三项合计数值正确

```
Given 当月有 2 笔支出（12.50、25.00）与 1 笔收入（8000.00）
When  我打开记账界面
Then  支出合计显示 ¥37.50，收入合计显示 ¥8000.00，结余显示 ¥7962.50
```

### AC-2 结余为负时负号可见

```
Given 当月支出合计 ¥100.00、收入合计 ¥30.00
When  我查看结余
Then  显示 -¥70.00 —— 负号必须看得见，不能显示成 ¥70.00
```

### AC-3 空月显示零并说明

```
Given 当月没有任何条目
When  我打开记账界面
Then  三项合计都显示 ¥0.00，并提示本月还没有记账
```

### AC-4 记一笔后合计立即更新

```
Given 当月支出合计为 X
When  我记一笔 ¥5.00 的支出并保存成功
Then  支出合计立刻变成 X + ¥5.00，不需要切界面或重开 App
```

### AC-5 删一笔后合计立即回退

```
Given 当月支出合计为 X（其中包含一笔 ¥12.50）
When  我删除那笔 ¥12.50 并确认
Then  支出合计立刻变成 X − ¥12.50
```

### AC-6 可翻看上一个月并回到当月

```
Given 当月是 2026-10，且 2026-09 有一笔 ¥60.00 的支出
When  我点「上一月」
Then  支出合计显示 ¥60.00，且界面明示统计的是 2026-09
      再点「下一月」回到 2026-10，显示当月的值
```

### AC-7 按发生时间归属月份

```
Given 我在 10-02 补记了一笔发生时间为 09-15 的支出
When  我查看 9 月的合计
Then  这笔计入 9 月（发生时间所在月），不计入 10 月
```

## 业务规则

| 编号 | 规则 | 理由 |
|---|---|---|
| `BR-1` | 月份边界按**本机时区**的自然月（`[月初 00:00, 次月初 00:00)`），半开区间 | 用户说的"这个月"是他日历上的月，不是 UTC 的月 |
| `BR-2` | 统计口径是条目的**发生时间**（`occurredAt`），不是录入时间 | 与列表排序依据一致（`REQ-001/AC-7`）；否则补记会同时出现在两个月里 |
| `BR-3` | 结余 = 收入合计 − 支出合计，**允许为负** | 用户问的就是"还剩多少"，负数（超支）正是最有价值的信息 |
| `BR-4` | 合计在**本机数据库**上计算，不联网 | 与整个项目一致（`PRIVACY.md`） |
| `BR-5` | 汇总**不改变**任何条目，也不产生新数据 | 它是读模型：`ADR-0005` 的物理删除意味着历史汇总只能靠当时的条目重算 |
| `BR-6` | 空月份合计为 `¥0.00` 而不是"没有数据 / 出错" | 没有记账与查询失败是两件事，界面必须区分（前者是正常状态） |
| `BR-7` | 未来的月份不进入（「下一月」在当月禁用） | 用户可以补记过去，但不会"预支未来"；`Q-021`（未来时间的账）在本卡不处理 |
