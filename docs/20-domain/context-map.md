## 上下文清单

| 上下文 | 类型 | 职责（一句话） | 拥有的聚合 | 模块 |
|---|---|---|---|---|
| | 核心域 / 支撑域 / 通用域 | | | `feature:` |

**类型说明**
- **核心域**：项目的竞争力所在，投入最强建模能力，模型要完整。
- **支撑域**：业务需要但不构成差异化，适度建模，够用即可。
- **通用域**：成熟方案，优先引入库或外购，**不要自研**。

## 上下文映射

| 上游 | 下游 | 模式 | 集成方式 | 说明 |
|---|---|---|---|---|
| | | | | |

**模式说明**

| 模式 | 含义 | 何时用 |
|---|---|---|
| Partnership | 双方共同演进，互相依赖排期 | 两个团队强绑定 |
| Customer-Supplier | 下游需求能影响上游排期 | 上游愿意配合 |
| Conformist | 下游顺从上游模型，不做翻译 | 上游不可协商且模型可接受 |
| **ACL（防腐层）** | 下游自己翻译，上游怎么变都不影响 | **默认选择**，尤其对接外部系统 |
| Shared Kernel | 共享一小块模型与代码 | 慎用，耦合代价高 |
| Published Language | 通过明确契约（OpenAPI/Proto）交流 | 跨团队/跨进程 |

## 共享内核

| 内容 | 位置 | 使用者 | 变更规则 |
|---|---|---|---|
| `Money`、`Outcome`、`DomainEvent` | `core:domain` | 全部 | 变更需受影响上下文共同确认 + ADR |

> 共享内核**越小越好**。只放真正的通用原语，不要往里塞业务概念。

## 跨上下文协作方式

| 场景 | 推荐方式 | 禁止方式 |
|---|---|---|
| 需要另一个上下文的**数据快照** | 事件携带快照 + 本地保存 | 同步查询上游聚合 |
| 需要触发另一个**行为** | 发布领域事件 | 直接调用上游 UseCase |
| 需要**强一致** | 合并上下文，或重新审视边界 | 跨聚合事务 |
