## 上下文清单（草稿）

| 上下文 | 类型 | 职责（一句话） | 拥有的聚合 | 模块 |
|---|---|---|---|---|
| **Ledger** 账本 | **核心域** | 记录一切钱的进出：手工/自动的收入与支出条目、分类（**v1 不含账户**，见 `ADR-0005`） | `LedgerEntry` | `feature:ledger` |
| **Worklog** 工时 | **核心域** | 基于地理围栏记录工作时段 | `WorkSession`、`Workplace` | `feature:worklog` |
| **Payroll** 薪资 | **核心域** | 按法定口径把月薪折算为日薪，再按日期类型与加班情况算出每日收入与工资单 | `Payslip`、`MonthlySalary` | `feature:payroll` |
| **Calendar** 工作日历 | 支撑域 | 判定某一天是工作日 / 休息日 / 法定节假日（含调休） | `WorkCalendar` | `feature:calendar` |
| **Insight** 统计 | 支撑域 | 日/周/月汇总与报表（**读模型，无聚合**） | — | `feature:insight` |

> **v0.3 变更（Q-012 澄清）**：薪资模型被**重建**。
> v0.2 假设工资是「工时 × 费率」，实际是中国法定月薪制：
> `日薪 = 月薪 ÷ 21.75`，再按 `工作日 1× / 休息日加班 2× / 法定节假日加班 3×` 计酬。
>
> 两个连带后果：
> 1. **Worklog 的职责收敛**——工时不再参与金额计算，只负责「判定某天是否加班」与工时统计
> 2. **新增 Calendar 上下文**——日期类型判定需要**中国法定节假日与调休数据**，
>    该数据由国务院每年发布且会跨年变化。它变化频率低、来源外部、
>    被 Payroll 单向依赖，符合「独立支撑域」的特征，不应塞进 Payroll。
>
> **v0.2 变更（Q-003 澄清）**：Allocation 上下文已删除——「按比例」指工资折算，不是收入分配。

### 为什么这样分

**为什么 Ledger 是核心域，而不是「记账」这个功能本身**

「记账」是通用域——市面上成熟方案极多，我们不该自己发明一套分类法。
但 Ledger 在本项目里承担了更关键的职责：**它是「钱」的唯一记录地**，
工资单最终要变成一笔 `LedgerEntry(Income)`，分配也要作用在收入条目上。
换句话说，Ledger 不是因为「记支出」而核心，而是因为它是其他上下文的汇聚点。

**为什么 Worklog 与 Payroll 分开**

Q-012 澄清后，这个判断变得更强了。工时**不参与金额计算**——
金额完全由 Payroll 自己按 `月薪 ÷ 21.75 × 倍率` 算出，
Worklog 只提供一个布尔式的事实：「这一天出勤了吗、属不属于加班」。

| | Worklog | Payroll |
|---|---|---|
| 守护的不变式 | 时段不重叠、地点有效、时长非负 | 月薪按生效日期取值、每日收入 = 日薪 × 倍率、周期不重复结算 |
| 提供什么 | 「哪天出勤了」 | 「那天值多少钱」 |
| 变化频率 | 每天多次 | 月薪几个月才变一次 |
| 失败影响 | 少记一次工时 | 算错钱 |

**为什么 Calendar 必须独立成上下文**

日期类型判定依赖**中国法定节假日与调休安排**——由国务院每年发布，且会调整
（某个周六可能被调成工作日）。它的特征：

| 特征 | 说明 |
|---|---|
| 变化频率低但**必然变化** | 每年至少更新一次，且历史年份不能改 |
| 来源外部 | 不是我们能推导的规则，是外部权威数据 |
| 被单向依赖 | Payroll 需要它，它不需要任何其他上下文 |
| 用错代价高 | 把休息日当工作日 → 少算双倍工资 |

按 AGENTS.md 第 6.4 节启发式 #3（变化频率）与 #6（宁可先粗后细，但边界清晰时不要硬塞），
它应独立。若塞进 Payroll，「节假日数据更新」就会变成「修改核心域」，
风险与测试成本都不成比例。

**为什么 Insight 是支撑域且没有聚合**

统计是从 Ledger/Worklog/Payroll/Calendar 派生出来的读模型。给它聚合会导致同一事实存两份，
违反 SSOT。它以 SQL 查询 / 投影实现，不拥有业务规则。

## 上下文映射（草稿）

| 上游 | 下游 | 模式 | 集成方式 | 说明 |
|---|---|---|---|---|
| Worklog | Payroll | Customer-Supplier | 领域事件 `WorkSessionConfirmed` | Worklog 只交付「某天出勤了」这一事实（`AttendedDay`）。**工时不参与金额计算**（Q-012）。`Running`/`Discarded` 的时段不计入 |
| Calendar | Payroll | **Conformist** | 同步查询 `DayType`（只读） | Payroll 顺从 Calendar 的日期类型定义，不做自己的翻译。二者同为本地数据，无需事件 |
| Payroll | Ledger | Customer-Supplier | 领域事件 `PayslipIssued` | 工资单产生一笔 `LedgerEntry(Income)`；跨聚合走最终一致 |
| Ledger / Worklog / Payroll / Calendar | Insight | Conformist | 直接读本地库（只读投影） | 读模型主动适应上游模型，上游不为其做适配 |
| 系统通知 / 短信 / 银行账单（外部） | Ledger | **ACL（防腐层）** | Mapper 把外部文本/结构化数据翻译成 `LedgerEntry` 草稿 | 取决于 Q-001/010/011；**外部格式的解析细节绝不进入领域层** |
| 定位服务（外部） | Worklog | **ACL** | 把坐标/围栏事件翻译成领域事件 | 系统定位 API 的变化被适配器吸收 |
| 法定节假日数据源（外部） | Calendar | **ACL** | 每年导入/更新节假日与调休数据 | 🔴 来源与更新机制待 Q-016；**外部数据格式绝不进入领域层** |

## 共享内核

| 内容 | 位置 | 使用者 | 变更规则 |
|---|---|---|---|
| `Money`、`EntryDirection` | `core:domain` | Ledger, Payroll | 变更需受影响上下文共同确认 + ADR |
| `Outcome`、`DomainError`、`DomainEvent` | `core:domain` | 全部 | 同上 |
| `TimeRange`（时间区间值对象） | `core:domain` | Worklog, Payroll, Ledger | 同上 |
| `LocalDate` 相关的日期类型 | `core:domain`（按需） | Calendar, Payroll, Ledger | 同上 |

> 共享内核**越小越好**。只放真正的通用原语。
> ⚠️ **`DayType`：语义归 Calendar，类型放共享内核** —— `ADR-0011` 决策 4 显式裁决了这里的一处冲突：
> 本文原写"不放共享内核"（一个**位置**问题），而"Payroll 通过 Calendar 的只读接口获取"
> 若按字面做就是 `feature:payroll → feature:calendar`，**直接违反 `R2`**。
> 裁决沿用 `ADR-0008` 的判例（与 `LedgerTotalsReader` 完全同构）：
> **端口与类型住内核，判定规则与实现住 `feature:calendar`，任何其他上下文不得重新定义一份。**
> —— 这不是放宽约束，而是把"谁能定义"从位置问题改成**所有权**问题。

## 跨上下文协作方式

| 场景 | 推荐方式 | 禁止方式 |
|---|---|---|
| Payroll 需要工时数据 | 订阅 `WorkSessionConfirmed` 事件，本地保存所需快照 | 直接 import `feature:worklog` 的聚合 |
| Ledger 需要工资单金额 | 订阅 `PayslipIssued` 事件 | 同步查询 Payroll 聚合 |
| Insight 需要跨上下文数据 | 只读投影 / SQL | 反向依赖各上下文的领域模型 |
| Worklog 需要知道费率 | **不订阅**。Worklog 只记时长，费率是 Payroll 的事 | 让 Worklog 持有 `PayRate` |

## 关键边界判断

| 判断点 | 结论 | 依据 | 状态 |
|---|---|---|---|
| 「自动捕获的消费」是 Ledger 内的聚合还是独立上下文 | **Ledger 内**，作为条目的一个来源字段 | 它是 `LedgerEntry` 的一种创建方式，不是独立业务能力 | 草稿 |
| 「工作地点」归 Worklog 还是独立 Place 上下文 | **Worklog 内** | 地点只在工时的语境下有业务含义 | 草稿 |
| 「费率」归 Payroll 还是 Worklog | **Payroll** | 费率只在结算时有意义 | 草稿 |
| 「分配目标」是否是一个聚合 | **不存在**——`Q-003` 澄清「按比例」指工资折算，Allocation 上下文已删除 | `Q-003` 已解决 | 已决 |
| 「账户」是否进 v1 | **不进**（延后）。账户一进来就会带出余额，而余额是**跨条目**的不变式——那是把「条目即聚合根」变成大聚合的第一步 | `Q-005` 已决；`ADR-0005` | 已决（`REQ-001`） |
| 是否需要独立的「用户/设置」上下文 | **不需要** | 单人使用，设置属于 UI 层 | 草稿 |
