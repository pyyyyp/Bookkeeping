## 契约使用规则

1. **原文入库**：拿到的契约文件原样放进本目录，不要在本地改写。
2. **变更走流程**：契约更新时——
   - 先 `diff` 识别破坏性变更
   - 新增或更新 ADR 说明影响面
   - 只改 `data` 层的 DTO 与 Mapper
   - 若**领域模型需要跟着改**，说明防腐层漏了，必须修正
3. **一个变更一个任务卡**：不要在一次提交里混入契约升级与业务功能。
4. **生成代码不入库**：由契约生成的代码放在 `build/` 或忽略目录，不提交。
5. **Mock 服务**：为便于并行开发，基于契约生成 Mock Server，脚本记在 `60-runbooks/build.md`。

## 变更检查清单

- [ ] 是否破坏性变更？（字段删除 / 类型变更 / 必填性变更 / 枚举值语义变更）
- [ ] 是否影响已发布版本的兼容性？需要灰度或版本并存吗？
- [ ] Mapper 是否已更新？测试是否覆盖新旧两种响应？
- [ ] 是否新增了 ADR？
- [ ] 是否更新了 `docs/90-trace/traceability.md`？
